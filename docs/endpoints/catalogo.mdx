# Catálogo

Autenticação: `X-API-Key` (ou token de aluno no painel).

## Listar produtos

<Endpoint method="GET" path="/v1/products" auth="X-API-Key" />

Aceita `search`, `categoryId`, `brandId`, `state`, `minPrice`, `maxPrice`, `page`, `pageSize`.

<Tabs groupId="lang">
  <TabItem value="curl" label="curl" default>

```bash
curl "$BASE/products?search=fone&page=1&pageSize=20" \
  -H "X-API-Key: $API_KEY" -H "X-Student-RM: RM550001"
```

  </TabItem>
  <TabItem value="resp" label="200">

```json
{ "data": [{ "id": "cmse...", "name": "Fone Bluetooth", "priceFrom": 199.9, "variantsCount": 1 }],
  "page": 1, "pageSize": 20, "total": 9 }
```

  </TabItem>
</Tabs>

## Detalhar produto (traz variantes)

<Endpoint method="GET" path="/v1/products/:id" auth="X-API-Key" />

:::tip A unidade vendável está aqui
Use `variants[].id` para carrinho e `variants[].price` para exibir o preço.
:::

## Criar produto

<Endpoint method="POST" path="/v1/products" auth="X-API-Key" />

<Tabs groupId="tipo">
  <TabItem value="simple" label="SIMPLE" default>

```json
{ "type": "SIMPLE", "name": "Carregador Turbo", "sku": "CARR-001", "price": 79.9, "stock": 60 }
```

  </TabItem>
  <TabItem value="variable" label="VARIABLE">

```json
{
  "type": "VARIABLE",
  "name": "Camiseta Gamer",
  "options": [{ "name": "Cor", "values": ["Preto", "Branco"] }],
  "variants": [
    { "sku": "CAM-PT", "price": 79.9, "stock": 10, "options": { "Cor": "Preto" } },
    { "sku": "CAM-BR", "price": 79.9, "stock": 5,  "options": { "Cor": "Branco" } }
  ]
}
```

  </TabItem>
</Tabs>

## Atualizar produto e variante

<Endpoint method="PUT" path="/v1/products/:id" auth="X-API-Key" />
<Endpoint method="PATCH" path="/v1/variants/:id" auth="X-API-Key" />

```json title="PUT /v1/products/:id (dados base)"
{ "name": "Novo nome", "state": "PUBLISHED", "categoryId": null }
```

```json title="PATCH /v1/variants/:id (preço)"
{ "price": 149.9 }
```

:::warning Estoque não é editado aqui
Preço vai no `PATCH /variants/:id`; **estoque** usa os endpoints de estoque
(`/v1/variants/:id/stock/receive` e `/adjust`).
:::

## Remover produto

<Endpoint method="DELETE" path="/v1/products/:id" auth="X-API-Key" />

Retorna `204 No Content`.

## Fotos e vídeos

<Endpoint method="POST" path="/v1/uploads" auth="X-API-Key" />
<Endpoint method="POST" path="/v1/products/:id/media" auth="X-API-Key" />

Os dois recebem `multipart/form-data` com o arquivo no campo **`file`**. O primeiro só
sobe para a biblioteca da loja; o segundo sobe **e já vincula** ao produto.

```bash title="sobe e vincula (uma chamada)"
curl -X POST "$BASE/products/$ID/media" \
  -H "X-API-Key: sk_live_..." \
  -F "file=@foto.jpg" -F "isPrimary=true"
```

```json title="resposta do POST /v1/uploads"
{
  "id": "cmu0...",
  "kind": "IMAGE",
  "url": "https://mockmerce-media.s3.us-east-1.amazonaws.com/groups/.../a1b2c3.jpg",
  "mimeType": "image/png",
  "sizeBytes": 48213
}
```

<Endpoint method="POST" path="/v1/products/:id/images" auth="X-API-Key" />
<Endpoint method="PATCH" path="/v1/images/:id" auth="X-API-Key" />
<Endpoint method="DELETE" path="/v1/images/:id" auth="X-API-Key" />

Vincula uma mídia já enviada (`mediaId`) ou uma URL externa (`url`); o `PATCH` troca a
capa ou a ordem; o `DELETE` desvincula (o arquivo continua na biblioteca).

```json title="POST /v1/products/:id/images"
{ "mediaId": "cmu0...", "isPrimary": true }
```

<Endpoint method="GET" path="/v1/media" auth="X-API-Key" />
<Endpoint method="GET" path="/v1/media/usage" auth="X-API-Key" />
<Endpoint method="DELETE" path="/v1/media/:id" auth="X-API-Key" />

Biblioteca da loja, espaço usado e remoção definitiva (`?force=true` quando o arquivo
estiver em uso por algum produto).

:::tip Detalhes e armadilhas
Formatos, limites, capa e o erro clássico do `Content-Type` estão no guia
[Fotos e vídeos](../guias/upload-de-midia).
:::
